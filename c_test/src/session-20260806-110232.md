## 1. 数据结构
- **`BMP_file_header`**(14 字节,`#pragma pack(1)` 紧凑对齐):BMP 文件头,`bfType`(0x4D42 = "BM")、`bfSize`、`bfOffBits`(像素数据偏移)等。
- **`BMP_info_header`**(40 字节):信息头,`biWidth`/`biHeight`、`biBitCount`(每像素位数)、`biSizeImage` 等。
- **`BMPCONTEXT`**:线程间共享的上下文,含像素缓冲 `pixels`、宽高、`rowSize`(每行字节数,按 4 字节对齐)和两个头。

## 2. 线程同步机制
全局 `g_mutex` + `g_cond` + 状态变量 `turn`,组成手写流水线:
- `turn = 0` → input 线程干活;`turn = 1` → process;`turn = 2` → output;`turn = 3` 结束。
- 每个线程进入后先 `while (turn != 自己的编号) pthread_cond_wait(...)`,干完活改 `turn` 再 `signal`,典型的「条件变量 + 状态轮转」。

## 3. 三个线程
| 线程 | 职责 |
|---|---|
| `input_bmp` | `open("input.bmp")` → 读两个头 → 校验是 24 位 BMP → 按 `rowSize = ((width*3+3)/4)*4` 分配像素缓冲 → `lseek` 到 `bfOffBits` 读像素数据 |
| `process_bmp` | 按 **20×20 块**遍历图像,对每块的 B/G/R 各通道求平均,再把块内所有像素写回平均值(即马赛克/像素化效果) |
| `output_bmp` | 更新 `bfSize`/`biSizeImage`,把头+像素写入 `output.bmp`,最后释放像素缓冲 |

`main` 依次创建/join 三个线程(每个线程传同一个 `ctx`),结束后 `free(ctx)`。

## 4. 值得注意的问题(阅读中发现)
- **错误路径死锁**:`input_bmp` 中若 `open`/校验/malloc 失败(如 `input.bmp` 不存在),直接 `goto` 返回,`turn` 永远停在 0——`process`/`output` 线程会**永久阻塞**在 `pthread_cond_wait` 上,`pthread_join` 卡死。
- **未检查返回值**:`read`/`write`(可能短读/短写)、`pthread_create`、`close` 的返回值都没检查。
- **`signal` 在 `unlock` 之前**:规范上应先 `unlock` 再 `signal`(当前顺序在单条件变量下多数情况仍能工作,但属于隐患)。
- **`biHeight` 用 `uint32_t` 存**:BMP 的负高度(自顶向下存储)经 `abs()` 处理时依赖隐式转换,行为有歧义。

**重构目标(三阶段模型):**

## 重构设计(待你确认)

### 1. 整体流程 — 三阶段,主线程串联

```
main()
├─ 阶段1 初始化: init_bmp(ctx)      // open/read/lseek 读 input.bmp、校验、申请像素内存
├─ 阶段2 处理:   将全部 20×20 块任务入队 → 创建 WORKER_NUM 个 worker 抢任务并行处理 → join 全部
├─ 阶段3 去初始化: deinit_bmp(ctx)  // write output.bmp、free 像素内存
└─ free(ctx)
```

相比现在的"三线程 + turn 串行",初始化/去初始化收归主线程,**并行只发生在处理阶段**,且是真正的多线程。

### 2. 任务队列(教学点:互斥锁保护共享状态)

```c
#define WORKER_NUM 4
#define BLOCK_SIZE 20

typedef struct { int x, y; } Task;            // 一个 20×20 块

typedef struct {
    Task   tasks[MAX_TASKS];                  // 一次性入队全部块
    int    head, tail, count;
    int    all_done;                          // 入队完毕标志
    pthread_mutex_t lock;
    pthread_cond_t  cond;
} TaskQueue;
```

- **入队**:处理阶段开始前,主线程把所有块 `(x, y)` 一次性 `push` 进队列。
- **worker 循环**:`lock → 队列空则 cond_wait → pop 一个任务 → unlock → 处理该块(算均值、写回)`。
- **结束条件**:worker 发现 `count == 0 && all_done` 即退出;主线程置 `all_done = 1` 后 `pthread_cond_broadcast` 唤醒所有在等待的 worker。
- **线程安全层次**(可讲透的两层):
  - 队列的 `head/tail/count` 读写全在 `mutex` 临界区内 —— 这就是"共享状态需要锁";
  - 像素数据本身:每个块只被一个 worker pop 走,写各自区域,天然无竞争 —— 这就是"数据分区可以不用锁"。

### 3. 保留并强化 fd 教学点
`init_bmp`/`deinit_bmp` 继续用 `open/read/write/lseek/close`,补上**返回值检查**(read 短读、write 短写、open 失败),失败走 `log_error` 并干净退出——顺带消除了原代码 input 失败导致 join 卡死的问题。
